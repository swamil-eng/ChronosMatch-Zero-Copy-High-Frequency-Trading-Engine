Match orders without serializing a byte.

Python processes hand orders to each other through shared memory. A C-level order book matches them, so the hot path never pickles an object or stops for the garbage collector.

The path of one order

Three things make Python a poor fit for this job: serializing data between processes, garbage-collection pauses, and interpreter overhead in the matching loop. Each stage below removes one of them.

Market simulator

An asyncio producer in its own process generates buy, sell and cancel orders, including occasional "whale" orders that sweep many price levels.

chronosmatch/simulator.py

Ring buffer

Producer and consumer map the same file. Each order is 32 bytes written in place with struct.pack_into. Nothing is pickled and no JSON is built.

chronosmatch/ringbuffer.py

Matching engine

Price-time priority on preallocated order slots and per-price queues. Automatic garbage collection is off while orders match; it runs only between batches, and the dashboard counts any pause that lands inside a match.

book_cy.pyx, book_py.py

Ledger and screens

A background thread batches every trade into SQLite for audit. The web dashboard and the curses terminal read the same live snapshot.

ledger.py, app.py

Run it

Python 3.10 or newer. Flask is the only required package; Cython is optional.

pip install -r requirements.txt
python app.py                           # website and dashboard at http://127.0.0.1:8000
python -m unittest discover -s tests -v

# optional: compile the Cython engine (needs a C compiler)
pip install cython
python setup.py build_ext --inplace

python tools/benchmark.py               # engine throughput and latency
python tools/ipc_audit.py               # ring buffer vs multiprocessing.Queue
python tools/dashboard_curses.py --local   # terminal dashboard
Educational simulation. ChronosMatch is not connected to a brokerage or exchange and is not for real trading.
